# 自宅サーバーへ外部から接続する

PSP クライアントを自宅 LAN の外から使う場合は、共有トークン認証を必ず有効にする。
`auth/token.txt` が無いサーバーは従来どおり認証なしで動くため、外部公開してはいけない。

## 共有トークンを設定する

サーバーのディレクトリで生成スクリプトを実行する。

```bash
cd apps/youtube-music/server
python3 tools/make_token.py
```

ランダムな共有トークンが `auth/token.txt` に保存される。既存ファイルは上書きしない。
その内容を、PSP の EBOOT と同じフォルダにある `server.txt` の 2 行目へコピーする。
1 行目は外部から到達できるホスト名とポートにする。

```text
myhome.example.net:49180
<auth/token.txt と同じトークン>
```

サーバーを再起動した後、トークン無しのアクセスが拒否されることを確認する。

```bash
curl -i http://127.0.0.1:8090/api/status
curl -i "http://127.0.0.1:8090/api/status?k=<トークン>"
```

最初の応答は 401、2 つ目は 200 になる。トークンを更新するときは
`auth/token.txt` を削除して生成し直し、`server.txt` の 2 行目も同じ値へ更新する。

## ルーターと DDNS を設定する

ルーターでは、外部側の高いポート番号をサーバーへ転送する。外部側に 8080 を
そのまま公開せず、たとえば 49180 のような別の高い番号を使うことを推奨する。
転送先はサーバーを起動している機器の LAN 内 IP アドレスと待受ポートにする。

家庭用回線のグローバル IP アドレスは変わることがある。IP が変わっても同じ接続先を
`server.txt` に書けるよう、ルーターまたはサーバーで DDNS を設定してホスト名を用意する。

## リスク

- PSP とサーバー間の通信は平文 HTTP である。公衆 Wi-Fi では共有トークン、検索内容、
  再生内容を盗聴される可能性がある。
- ルーターで開けたポートは常にインターネットからの攻撃対象になる。OS、Python の依存、
  yt-dlp などを更新し、不要になったポート転送は閉じる。
- YouTube を経由する利用には規約上のリスクがあり、その責任は利用者が負う。

共有トークンは接続者を制限するためのもので、通信を暗号化するものではない。

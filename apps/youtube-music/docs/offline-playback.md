# オフライン再生の設計

「MacBook（サーバー）を通さずどこでも聴きたい」という要望への回答。
サーバーを外へ出す案（VPS 等）は PSP の TLS 制約と YouTube の
データセンター IP ブロックで筋が悪いため、**曲を PSP 本体へ持ち出す**方式にした。

```
[家: サーバー稼働中]  □ でダウンロード → ef0:/PSP/GAME/YTMUSIC/offline/ に保存
[外: サーバー不在]    オフライン ライブラリからローカル再生 (ネットワーク不要)
```

## ファイル配置

EBOOT と同じフォルダの `offline/` 配下。

| ファイル | 内容 |
|---|---|
| `<videoId>.mp3` | サーバーが配信するものと同じ MP3 CBR 128kbps / 44.1kHz / stereo |
| `<videoId>.art` | 64x64 RGBA 生ピクセル (サーバーの /art と同じ形式) |
| `index.tsv` | 1 行 = 1 曲: `videoId \t 曲名 \t アーティスト \t 秒` |

- 形式をサーバー配信と完全に一致させることで、**デコード経路が再生と共通**になる
  (sceMp3 / テクスチャ転送のコードを一切増やしていない)
- `index.tsv` は追記ではなく毎回全書き。削除と経路を揃えて単純化
  (500 曲でも数十 KB なので性能問題にならない)

## モジュール構成

| ファイル | 役割 |
|---|---|
| `src/store.c` | 索引の読み書き・ファイルパス解決。UI/DL 両スレッドから呼ばれるため内部ロック |
| `src/dl.c` | ダウンロードスレッド。キューから 1 曲ずつ `/stream?yt=` を `.part` に保存 → 完走したら `.mp3` へ改名 → `store_add` |
| `src/player.c` | `player_start` 時に `offline/<id>.mp3` があればソケットではなくファイルから読む (供給元の分岐のみ、デコードは共通) |
| `src/art.c` | ワーカーがネットワークより先に `offline/<id>.art` を見る。オフライン時はこれが唯一の供給源 |

## 設計判断

- **`.part` → 改名**: 途中で切れたファイルを索引に載せないため。
  64KB 未満はサーバーのエラー本文とみなして捨てる
- **長さ不明の曲はファイルサイズから概算** (128kbps CBR = 16000 バイト/秒)。
  ホームの単曲カードは duration を持たないため
- **ダウンロード済みの曲はオンライン時もローカル再生**。
  挙動が一本化され、再生開始も速い
- **再生キューへの取り込みは最大 100 曲** (`API_MAX_TRACKS` の再利用)。
  100 曲超を保存している場合は選択曲以降を積む。索引上限は 500 曲
- **接続失敗画面から ○ でオフライン起動**。外出先では Wi-Fi 接続自体が
  失敗するので、この経路が実質のオフライン起動導線になる
  (`net_init` の失敗・サーバー不達のどちらでも入れる)

## 実装時に踏んだ地雷

- **sceIoRename / sceIoRemove は相対パスを解決しない** (PPSSPP で実測)。
  `.part` は fopen で書けるのに `.mp3` への改名だけ静かに失敗し、
  「.part が大量に残り index.tsv が空」という症状になる。
  EBOOT 相対のファイル操作は stdio (`fopen` / `rename` / `remove`) に統一した
- SHOTDUMP (アプリ自身のフレームバッファ書き出し) は PPSSPP では真っ白になる。
  目視確認は winshot (`~/.claude/skills/winshot/winshot.sh PPSSPP out.png`) を使う

## 検証方法 (2026-07-27 実施・全経路確認済み)

1. `make AUTODEMO=1`: ホームとプレイリストで □ (ダウンロード) も自動入力する。
   PPSSPP で走らせ、`~/.config/ppsspp/PSP/GAME/YTMUSIC/offline/` に
   `.mp3` / `.art` / `index.tsv` が生成されることを確認
2. サーバーを止めて再起動 → エラー画面に「○: オフライン再生 (N曲)」→
   ○ でライブラリ (ローカル .art でアートワーク表示) → ○ でローカル再生が進む
